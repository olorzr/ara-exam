# AI 추천 빈칸 — 마킹 기준의 근거

`src/lib/concept-pick/prompt.ts` 의 규칙은 짐작이 아니라 **선생님이 손으로 마킹해 둔 개념지를
세어 만든 값**이다. 프롬프트를 고칠 때는 이 문서의 실측표를 먼저 볼 것.

## 어떻게 셌나 (2026-09-15)

`exam.concept_sheets` 전체 121장을 읽어, `print_bundle_id IS NULL` 이면서 마킹이 있는
**개념지 120장 / `<mark data-concept>` 8,100개**를 셌다. 본문 길이는 `editor_html` 의
보이는 글자 수(`textContent`)다. AI 추천 기능은 2026-09-15 에 처음 나갔으므로 그 시점의
저장된 마킹은 사실상 전부 손 마킹이다(마킹에는 출처를 적는 속성이 없다 — `updated_at` 말고는
둘을 가릴 방법이 없다).

같은 날 AI 가 뚫은 학교 프린트 시험지 3장이 비교군이다.

## 실측

### 양 — AI 가 선생님의 1/5 만 뚫고 있었다

| | 1,000자당 빈칸 |
|---|---|
| 선생님 개념지 120장 (중앙값) | **52.4** |
| AI 프린트 '하늘은 맑건만' | 9.2 |
| AI 프린트 '홍길동전' | 12.7 |
| AI 프린트 '아파트먼트 셰르파' | 14.4 |

장당 중앙값 60개(평균 67.5), 본문 글자 중앙값 1,235자. 가장 빽빽한 장은 3,605자에 229개.
→ 프롬프트는 **밀도**(100자당 5개)로 말한다. '장당 10개 안팎' 같은 절대 개수로 되돌리면
본문이 길수록 더 크게 어긋난다.

### 자리 — 97.9% 가 표 안이다

| 위치 | 수 | 비율 |
|---|---|---|
| 표 칸 | 7,926 | 97.9% |
| 문단 | 162 | 2.0% |
| 목록 | 12 | 0.1% |

표 안에서의 열 위치: `2열 표의 2번째 칸` 4,364 · `1열 표` 2,255 · `2열 표의 1번째 칸` 392 ·
`3열 표의 3번째 칸` 358. → **라벨(왼쪽) 칸이 아니라 내용(오른쪽) 칸**이다.
라벨 칸에 뚫린 392개는 라벨 자체가 외울 용어인 경우다(된소리·파열음·정의·인과·발단·절정·상형의 원리).

표 행 2,892개 중 **2,330개(80.6%)** 에 빈칸이 있다. 행당 빈칸 수는 1개 556 · 2개 555 ·
3개 402 · 4개 260 행으로 이어진다. 마킹된 칸 안에서 **어절의 29%**(중앙값)가 빈칸이다.

### 낱말 모양

| | 값 |
|---|---|
| 길이 중앙값 | 2자 |
| 2자 / 3자 | 66.5% / 19.8% |
| 1자 | 5.6% (뜻·꿈·말·삶·힘·글) |
| 공백이 든 것 | 4.3% |
| 조사·어미로 끝나는 것 | 2.2% |
| 칸을 통째로 뚫은 것 | 3.5% (나머지는 칸 **속** 낱말) |

접미사가 붙은 말은 어근만 뚫는 쪽이 많다: `적` 342 · `성` 166 · `음` 123 · `화` 106
(`【설득】적`, `【객관】적`). 쉼표로 나열된 짧은 칸(갈래·성격·소재)은 항목 639개 중
**495개(77%)** 가 뚫려 있다 — `【사실】적, 【고백】적, 【성찰】적`.

### 자주 뚫는 말 — '흔한 일반어 금지' 는 틀린 규칙이었다

장 수 기준 상위: 목적(29) 이해(27) 주제(26) 갈등(21) 사실(20) 해결(20) 상황(19) 문제(19)
내용(19) 시간(18) 요약(18) 정보(17) 관심(17) 경험(17) 감정(17) 뜻(17) 주장(17) 근거(16)
흥미(16) 설득(15) 대상(15) … 사람(11) 생각(14) 말(12) 자연(9).

옛 프롬프트는 "'것'·'사람' 같은 흔한 일반어는 고르지 않는다" 고 적고 있었다. 실제 기준은
**낱말이 흔한지가 아니라 그 문장의 알맹이인지**다.

### 뚫지 않는 말

마킹된 칸 안에서 **끝까지 안 뚫린 어절** 상위: •(1,220) 수(359) 있음(238) 함(202)
있는(142) 내용을(123) 대한(104) 자신의(98) 글의(93) 때(71) 하는(69) 등을(69) 다른(66)
통해(64) 따라(62) 잘(62) 다양한(57) 위해(52) 줌(51) 제시함(37) 사용하여(37) 쉽게(32).

→ 기능어·꾸밈말·서술어, 그리고 **문장의 틀이 되는 말**(글·내용·자료·독자)이다.
`글의 【주제】와 【목적】에 맞는 자료를 찾아 내용을 마련한다` 가 전형이다.

### 프린트 시험지는 모양이 다르다

개념지는 표가 본체지만, 학교 프린트를 읽어 만든 시험지는 `N. 물음 … 답: 정답` 꼴의 문단이다
('하늘은 맑건만' 50줄 중 표 0줄). 선생님 기준을 그대로 옮기면 **빈칸은 '답:' 뒤 문장에만**
들어간다 — 물음에 구멍이 나면 문제 자체가 사라진다. 실제로 옛 AI 마킹은 발문에도 뚫었다
(`2. 수만이의 【괴롭힘】`).

## 알고도 따르지 않은 것

| 선생님이 하는 일 | 왜 안 따르나 |
|---|---|
| 한 글자 뚫기 (5.6%) | `findMarkTarget` 의 `indexOf` 가 더 긴 낱말 **안쪽**을 잡는다('시' 가 '자유시' 안에서). 엉뚱한 자리에 구멍이 나는 쪽이 몇 개 놓치는 것보다 나쁘다 (`CONCEPT_PICK_TEXT_MIN`) |
| 같은 낱말을 여러 자리에 (23.9%) | `addMarkByText` 는 한 낱말에 **한 자리**만 붙인다. 되풀이를 허용하려면 마킹 쪽을 먼저 고쳐야 한다 |
| 두 어절 뚫기 (4.3%) | `extractMarks` 가 공백으로 쪼개 세어 **문항 수 = 합격 기준의 분모**가 부푼다. 대신 낱말마다 따로 내게 한다 |

## 다시 세려면

스크립트를 남겨 두지 않았다 — 한 번 쓰는 분석이고, 세는 기준(위치·어절·접미)이 매번 달라진다.
한 줄 최대 358자, 1,000자를 넘는 줄은 0개였다(묶기 상한의 근거). `editor_html` 을 `jsdom` 으로 읽어 `mark[data-concept]` 의 `closest('td,th')` 와 행·열 번호를
세면 위 표가 그대로 나온다.
